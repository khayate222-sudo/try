# pawplay

スマホのブラウザで遊ぶ、猫のための小さな狩りゲーム。ねずみ・てんとうむし・羽・小さなアリ・小バエ・蜘蛛・ひらひら紐、速度3段階、草原／夜の庭、効果音の切り替えに対応。獲物は移動・静止・隠れる動作をランダムに切り替えます。設定は端末内に保存されます。通常のゲームは外部API不要です。端末間リモコンにはPeerJSの接続サービスを利用します。

## ステージ

- **平面の狩り場**：従来の猫動画のような見下ろし画面。獲物が走る・止まる・隠れる動作を切り替えます。移動を高速化し、速度は「ゆったり・すばやく・猛ダッシュ」の3段階です。
- **奥行きダッシュ**：前に走り続ける一人称の遠近感をCanvasで描画。道や木々が手前へ流れ、奥から来る獲物が左右・上下に揺れながら近づきます。通過前にタップすると、距離に応じて30／20／10ポイント。通過した獲物は得点になりません。獲物の種類、速度、草原／夜の庭を両ステージで選べます。

- **壁のぼり**：蜘蛛や小さな虫が正面の壁をのぼります。短いダッシュ、探索、停止、急旋回をランダムに切り替え、近くへのタップから逃げます。てんとうむし・アリ・小バエ・蜘蛛・紐を選べ、ねずみと羽はこのステージでは無効です。小さなアリ・小バエは捕獲で20点、他は10点です。

虫の動きは平面・奥行き・壁で共通の不規則な運動モデルを使います。脚は移動距離に連動して動き、止まっている間は歩き続けません。虫の色を「くっきり」にすると、明るい背景では黒っぽく、暗い背景では淡い色に変わります。「自然な色」では茶色系になります。大きさは「極小・ふつう・大きめ」。小さい虫でもタッチ判定を最低18pxに保ちます。

「ひらひら紐」は先端に遅れてしなる14節の紐で、止まっているときも末端が風に揺れます。全ステージで選べ、自動モードでは先端だけでなく紐の途中でも捕獲できます。飼い主モードでは指で振る・止める・隠す動きで遊べます。

ステージは設定画面のカードで切り替えます。プレイごとに得点をリセットし、休憩画面に今回のポイント・捕獲数・時間を表示します。描画や判定に外部3Dライブラリは使いません。

## ミラーリングなしでTVとiPhoneをつなぐ

1. TVのSilkなどのブラウザで公開サイトを開き、**TV・PC側で接続コードを出す** を選びます。WebRTC非対応のブラウザでは対応できない旨が表示されます。
2. iPhoneのカメラでTVのQRコードを読み取ります。またはiPhoneでも同じサイトを開き、**iPhone側で操作する** から8文字のコードを入力します。
3. 接続すると、TV側にゲーム、iPhone側に操作パッドが出ます。操作パッドを指でなぞるとTVの獲物が動きます。
4. iPhoneから種類・平面／壁・背景・サイズ・虫の色・表示／非表示・休憩／再開を変更できます。奥行きダッシュは自動モードで使います。

AirScreenなどのミラーリングアプリは使用しません。PeerJS 1.5.5の公開接続サービス（`0.peerjs.com`）で最初の接続を仲介し、操作はWebRTCデータチャネルで送ります。受信機やルーターの条件によってはライブラリ標準のSTUN／TURNが使われます。カメラやマイクの権限は要求しません。QRコードはURLのフラグメントに部屋コードを入れます。コードは端末の暗号学的乱数から生成し、1台の操作端末だけを受け付けます。

両端末のインターネット接続とWebRTC対応が必要です。同じWi-Fiを推奨します。ゲスト用ネットワークの端末間隔離、VPN、企業ネットワークの制限で接続できないことがあります。接続サービスの稼働や無料提供の継続を保証するものではありません。Fire TVでページが開けることだけではWebRTC対応や実機での接続成功は確認できません。非対応の場合は、PCなど対応ブラウザでの表示や従来のミラーリング方式を使います。

接続が切れる／7秒以上応答がない場合はTVを一時停止し、同じコードで再接続できます。iPhoneがバックグラウンドに移ると休憩します。TVで接続画面を閉じるかゲームを終了すると接続を破棄します。再接続時も設定・表示状態・一時停止をTV側から受け取ります。

## iPhoneの画面自体をTVに映す（従来の方式）

「あそび方をえらぶ」から **飼い主が動かす** を選びます。平面・壁のステージで、画面をなぞると獲物が指についてきます。指を離すと最後の位置で止まり、「かくす／出す」で表示を切り替えられます。操作モードも保存されます。このモードでは捕獲ポイントを付けず、奥行きダッシュと自動速度の設定は使いません。自動モードに戻すと従来の全ステージと捕獲を利用できます。

TVにはiPhoneの**画面全体をミラーリング**します。ゲーム内の「TVへの映し方」に手順があります。

1. iPhoneとTV側受信機を同じWi-Fiに接続します。
2. AirPlay対応TV／Apple TVはAirPlay受信を有効にします。Fire TV Stickの場合は、AirScreenなどのAirPlay受信アプリをインストールして起動します（対応・料金は各アプリの案内を確認してください）。
3. iPhoneのコントロールセンター → 「画面ミラーリング」から受信先を選択します。
4. Safariでゲームを開き、飼い主が動かすモードで遊びます。横向き表示にも対応しています。

画面ミラーリングの接続はiPhoneと受信機の機能で行います。このアプリは独立したTV受信画面や機器検索、リモート接続サーバーを実装していません。iPhoneとTVに同じ画面が映り、TVでのタッチは入力されません。実機のAirPlay／Fire TV接続は自動テストの対象外です。接続可否と遅延は受信機・受信アプリ・Wi-Fi環境によって変わります。

## 開発

Node.js 22以上で実行します。

```sh
npm ci
```

```sh
npm start
npm test
npm run build
npm run test:remote
```

標準ポートは3000（`PORT`で変更可能）。`npm run build` は公開用ファイルのみを `dist/` にコピーします。`dist/` をHTTPS対応の静的ホスティングに配置するとスマホから使えます。ソースの場所にかかわらず実行でき、サブディレクトリ配下にも対応しています。

`npm run test:remote` はローカルのPeerJS接続仲介サーバーと2つのブラウザで、本物のWebRTC接続・指操作の反映・設定同期・切断時の停止・再接続を検証します。ChromiumまたはGoogle Chromeが必要です（`CHROME_PATH`でも指定可能）。`REMOTE_PUBLIC=1 npm run test:remote` は公開PeerJSサービスを経由する同じ検証です。ローカル環境の管理ポリシーがWebRTCのUDP通信を無効化している場合は接続検証を実行できません。GitHub Actionsでは両方のブラウザ検証を公開前の必須チェックとして実行します。

## GitHub Pagesで公開

`.github/workflows/pages.yml` にテスト → ビルド → 公開の設定があります。

1. このコードを `main` にpushします。
2. [リポジトリのPages設定](https://github.com/khayate222-sudo/try/settings/pages) で、Build and deployment の Source に **GitHub Actions** を指定します。利用プラン・組織のポリシーによりPagesを有効化できない場合は、別の静的ホスティングが必要です。
3. Actionsタブから **Publish pawplay** を実行します。有効化前に失敗した実行は再実行してください。以降は `main` の更新で公開されます。
4. 実行結果に表示される `github-pages` のURLをスマホで開きます。独自ドメイン設定がない場合の予定URLは `https://khayate222-sudo.github.io/try/` です。デプロイ成功とHTTP応答を確認するまでは公開済みとは見なせません。

## スマホでの操作

- プレビューもタッチできます。相手と背景を選び、画面下のボタンで開始します。
- 獲物にタッチすると捕獲。休憩ボタンは約1秒長押し（キーボードではEnterまたはEscape）。3分ごとに休憩画面が表示され、別タブに移ると一時停止します。
- iPhoneは共有メニュー、Androidはブラウザのメニューから「ホーム画面に追加」が可能です。初回のオンライン読み込みとサービスワーカーの準備完了後は、オフラインでも遊べます。ブラウザ設定でストレージが制限されるとオフライン機能は利用できません。
- スリープ抑止は対応ブラウザのHTTPS接続で利用します。通常のブラウザ表示ではOSとブラウザの操作領域が残ります。

猫の反応には個体差があります。スマホを平らな場所に置き、見守りながら短時間ずつ遊んでください。音は初期状態でオフです。画面遊びの後には、本物のおもちゃで捕まえる遊びもどうぞ。
